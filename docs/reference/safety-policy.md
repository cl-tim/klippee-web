# Safety Policy

Klippee should assume every raw config import may contain private details,
generated machine state, or files that are unsafe to share.

Safety rules apply most strictly to public packages. Private repositories may
store sensitive files, but the app should still warn users when it detects them.

## Risk Categories

### Secrets

Block public publishing when files contain likely secrets.

Patterns to detect:

- JWTs
- API keys
- passwords
- bearer tokens
- private keys
- OAuth tokens
- webhook URLs with embedded credentials

Example risky keys:

```text
token
password
secret
api_key
apikey
authorization
bearer
```

### Network Identity

Warn before publishing local network details.

Examples:

- static IP addresses
- local hostnames
- trusted client ranges
- CORS domains
- camera stream URLs

Some network details may be normal in Moonraker configs, so these should be
warnings rather than automatic hard blocks unless credentials are present.

### Runtime State

Exclude runtime state from public packages by default.

Examples:

- `saved_variables.cfg`
- bed mesh state generated by the printer
- files written by macros during normal operation
- temporary logs

### Backups and Archives

Exclude backups and archives from public package contents by default.

Examples:

- `*.bak`
- `*.bkp`
- `*.7z`
- `*.zip`
- `*.tar`
- timestamped config backups

Large archives can be stored as private import artifacts, but they should not be
normal synced package files.

### Machine-Specific Devices

Warn on machine-specific device paths. For reusable public packages, prefer
turning these into declared variables instead of publishing the raw value.

Examples:

- `/dev/serial/by-id/...`
- `/dev/v4l/...`
- camera device identifiers
- USB vendor/product IDs
- CAN UUIDs
- Beacon probe serial paths

These are useful for real printer configs but can confuse users who copy a
package directly.

## Variables and Public Safety

Machine-specific values that are required for a config to run should be modeled
as package variables.

Example:

```ini
[beacon]
serial: ${KLIPPEE:beacon_serial}
```

Public package files may contain Klippee placeholders. Public package files
should not contain the original user's resolved hardware IDs unless the value is
generic and intentionally shared.

Variable values belong to a private printer installation profile. They should be
shown only to the package owner or printer owner.

## Severity Levels

### Block

The package cannot be published publicly until the issue is resolved.

Use for:

- detected secrets
- private keys
- credential-bearing URLs

### Warn

The package can be published only after the user explicitly confirms or edits
the file.

Use for:

- local IPs
- trusted client ranges
- CORS domains
- device paths
- machine-specific calibration values

### Info

The package can be published, but the UI should explain the finding.

Use for:

- generated comments
- unknown file roles
- optional accessory configs

## Default Ignore Rules

Recommended default ignore patterns:

```gitignore
.klippee/
saved_variables.cfg
config.mksini
*.bak
*.bkp
*.7z
*.zip
*.tar
*.tar.gz
*.log
printer-[0-9]*.cfg
printer_*_*.cfg
gcode_macro_[0-9]*.cfg
```

## Redaction

The importer may offer redaction for private values, but redaction should create
a new file version and preserve the original only in private storage.

Suggested placeholder format:

```text
<KLIPPEE_REDACTED:token>
<KLIPPEE_REDACTED:local_ip>
```

## Log improvement contributions

Browser log analysis remains local by default. A source log may be retained for
analyzer improvement only after a signed-in user deliberately opens the
contribution form and confirms both that printer information will be shared
with Klippee developers and that they reviewed the file for anything they want
to redact.

Improvement samples must:

- remain private and require the dedicated developer review secret
- be stored as gzip rather than plain text
- record the consent version and consent time
- expire and be deleted after 90 days
- allow the contributor to withdraw the just-created submission

The consent notice must call out configuration, hardware identifiers, serial
paths, hostnames, IP addresses, file paths, macro output, and print filenames
as examples of information that logs may contain.

## Current Seed Repo Notes

The current raw seed configs include:

- JWT-looking `token` values in `config.mksini` files.
- Moonraker authorization and CORS sections.
- Webcam device paths.
- Runtime `saved_variables.cfg` files.
- Backup files and a large `.7z` archive.

These examples should drive importer tests and safety scan fixtures. Folder
import should reject them by path before file contents enter the browser
workspace.
